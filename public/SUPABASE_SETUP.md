# EHO — Supabase setup (simple steps)

You only need to do this once. It takes about 10 minutes.

---

## Step 1 — Connect the website to your Supabase project

1. Open <https://supabase.com/dashboard> and click your EHO project.
2. Go to **Project Settings → API** (sometimes called **API Keys / Data API**).
3. Copy two values:
   - **Project URL** — looks like `https://abcdxyz.supabase.co`
   - **anon / publishable key** — a long text starting with `eyJ…` or `sb_publishable_…`
4. In the project folder, copy the file `.env.example` and name the copy **`.env.local`**.
5. Open `.env.local` and paste your values:
   ```
   VITE_SUPABASE_URL=https://abcdxyz.supabase.co
   VITE_SUPABASE_ANON_KEY=paste-the-anon-key-here
   ```
6. **Restart the dev server**: press `Ctrl + C` in the terminal, then run `npm run dev` again.
   (Vite reads `.env.local` only when it starts.)

> ⚠️ Never put the **service_role / secret** key in `.env.local`. Everything starting with `VITE_` is visible in the browser.

---

## Step 2 — Create the database tables and functions

1. In Supabase, open **SQL Editor → New query**.
2. Open the file `supabase/schema.sql` from this project, copy **all** of it, paste it, click **Run**.
3. New query again: copy all of `supabase/fix_admin_access.sql`, paste, **Run**.
   At the bottom you will see a table of all login accounts with an `is_eho_admin` column.

Both files are safe to run more than once.

---

## Step 3 — Create your admin login and make it an admin

1. In Supabase go to **Authentication → Users → Add user → Create new user**.
   Enter your email and password and tick **Auto Confirm User**.
   (If the user already exists, skip this.)
2. **SQL Editor → New query**: paste `supabase/grant_admin.sql`.
3. Change `YOUR_ADMIN_EMAIL@example.com` to your real email (keep the quotes). Click **Run**.
   You should see: `Done: you@example.com (...) is now an EHO administrator.`
4. Open <http://localhost:5173/admin> and sign in.

---

## If something goes wrong — what each screen means

| What you see on /admin | Meaning | Fix |
|---|---|---|
| **Admin sign-in setup** | `.env.local` missing or wrong | Step 1, then restart `npm run dev` |
| **Incorrect email or password** | That login does not exist in *this* Supabase project, or wrong password | Check Authentication → Users of the project in `.env.local` |
| **Administrator access required** | Login works, but the account is not in `eho_admins` | Step 3 (`grant_admin.sql`). The screen also shows your user ID |
| **Could not verify administrator access** + "function … not found" | `schema.sql` / `fix_admin_access.sql` not run in this project | Step 2, then click **Try again** |
| **Could not verify** + "permission denied" / "session expired" | Old login session | Click **Sign out**, sign in again; if it repeats, run `fix_admin_access.sql` |
| **Could not reach Supabase** | Internet problem or wrong URL | Check connection and `VITE_SUPABASE_URL` |

**Most common cause of "it used to log in, now access denied":** the website is connected to a different
Supabase project than the one where you made yourself admin, or the admin row was never added.
The error screen shows which project is connected (`xxxx.supabase.co`) — compare it with your dashboard URL.

## Deploying (Netlify etc.)
Add the same two variables (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) in the hosting dashboard
(Netlify → Site configuration → Environment variables), then redeploy.

## Certificate workflow
- Visit `/admin` and sign in with the admin account.
- **Certificates** tab: issue, search, print / save as PDF, or revoke (a reason is required).
- Certificate IDs are generated by the database and are unique.
- Public verification: `/verify/` or `/verify/EHO-YYYY-...`. Revoked certificates show as REVOKED.
- The printed certificate loads its QR code from a third-party QR service (api.qrserver.com), so the public verification link is sent to that service. The PDF has no cryptographic signature; the online verification record is the source of truth.

## Security notes
- No passwords or secret keys are stored in this project.
- Admin rights are checked by the database (`is_eho_admin()` uses the logged-in user's verified ID), and checked again inside every certificate issue/revoke function. Changing the website code in a browser cannot bypass this.
- Row Level Security stays enabled on every table. Browsers can never read or edit the `eho_admins` table.
- Keep public sign-ups disabled in Supabase (Authentication → Sign In / Providers → turn off "Allow new users to sign up") so strangers cannot create accounts.
- Course / domain / internship / site-setting edits in the admin studio are still saved in **this browser only** (localStorage). Use **Export backup** to keep them.
